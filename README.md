# AVR development environment template

This tree is the C99 baseline: an Arduino Mega 2560 (ATmega2560 at 16 MHz), avr-libc, avr-gcc, FreeRTOS, USB bootloader flashing, and AVR Dragon ISP/JTAG for the point where the bootloader comes off. A second board file is the starting point for an ATmega1284P or another AVR.

## Layout

```
Makefile                  board selection, build, flash, fuses, debug
boards/atmega2560.mk      Arduino Mega 2560
boards/atmega1284p.mk     bare 1284P template
include/FreeRTOSConfig.h  kernel and tick-source settings
src/                      FreeRTOS application, USART0 console, LED, blink test
third_party/              FreeRTOS-Kernel V11.3.2 plus one local patch
.devcontainer/            Debian image, plus host serial and USB links
tools/                    fetch script, compile-commands generator, gdbinit, Dragon udev rule
compile_commands.json     generated by make; not committed
```

`make help` lists the targets.

## Dev container

Reopen the folder in the dev container. The image is Debian bookworm and installs the distribution AVR toolchain: avr-gcc 5.4.0, binutils-avr, avr-libc 2.0.0, avrdude 7.1, AVaRICE 2.14, and avr-gdb. Clangd is not in the image. The first start runs `make all`.

`make` writes `build/atmega2560/stepper-interface.hex` and refreshes `compile_commands.json`. `build/stepper-interface.elf` is a symlink to whichever board was linked last.

The container keeps its own `/dev`. It bind-mounts the Docker host's `/dev` at `/dev/host-dev`, and `.devcontainer/host-dev-links.sh` links `ttyACM0`, `ttyUSB0`, and `bus/usb` into `/dev`. Those mounts exist only after **Dev Containers: Rebuild Container**. A window reload keeps the old container, whose prompt still shows the old id and whose `/dev` has no `host-dev`. A board attached after that rebuild shows up through the links. See USB flashing for `usbipd`.

## Firmware

`src/blink.c` is the toolchain smoke test. It does not link FreeRTOS. On the Mega the "L" LED (PB7, Arduino digital 13) is on for one second and off for one second. `make blink` writes `build/atmega2560/blink.hex`. `make flash-blink` uploads it through the USB bootloader and leaves the bootloader in place.

`src/main.c` starts FreeRTOS and a heartbeat task. On the Mega it toggles that same LED every 500 ms and writes a line to USART0 at 115200 8N1:

```
heartbeat 12 stack 280
```

USART0 is the USB-serial bridge on the Mega (PE0/PE1, Arduino pins 0 and 1). On a 1284P the same registers are PD0/PD1. `stack` is the FreeRTOS high-water mark in bytes from `uxTaskGetStackHighWaterMark2`. This port's `UBaseType_t` is 8 bits, so the plain high-water API saturates at 255; the `2` variant does not.

An assert, stack overflow, or failed allocation disables the watchdog and blinks the LED quickly.

The scheduler tick is Timer0 in CTC mode at 100 Hz (`configAVR_USE_TIMER0_TICK` in `include/FreeRTOSConfig.h`). The port's divide-by-1024 makes that rate land on about 100.2 Hz at 16 MHz, and it leaves the watchdog off so a fault cannot lock the Mega's USB bootloader. Timer1, Timer3, Timer4, and Timer5 stay free for step pulses. Step generation for the HBS86H belongs in a 16-bit timer ISR, not in a task delay. `src/blink.c` also clears the watchdog at startup, because a watchdog reset sets WDRF and that forces the watchdog back on.

Set `configAVR_USE_TIMER0_TICK` to 0 to use the enhanced watchdog interrupt (about 16 ms, `WDTO_15MS`) and free Timer0 as well. That can wedge an old Mega bootloader if the CPU hangs with the watchdog armed; keep the Dragon in reach before switching. Run `make clean` after changing it.

Stack sizes in this port are bytes (`StackType_t` is `uint8_t`). The Mega heap is 4096 bytes inside the SRAM total that `make` prints. Task functions on the 2560 are placed in `.lowtext`, which the avr6 linker script gathers at the start of flash, because the port stores a 16-bit task entry point.

## USB flashing

The Mega's bootloader speaks stk500v2. `make flash` uploads the FreeRTOS image and `make flash-blink` uploads the blink image. Both call avrdude's `wiring` programmer at 115200 baud and do not erase the bootloader. The link reserves the top 8 KiB (text region of 253952 bytes). The port is `/dev/ttyACM0` when that node exists (official Mega, 16U2) and `/dev/ttyUSB0` otherwise (CH340 clones). Override with `USB_PORT=`.

On WSL2, attach the board to the same distro that runs Docker:

```sh
usbipd list
usbipd bind --busid <id>
usbipd attach --wsl --busid <id>
```

Confirm the node in that distro (`ls /dev/ttyUSB0 /dev/ttyACM0`). Inside the container, after a rebuild:

```sh
ls -l /dev/ttyUSB0
make flash-blink
```

`/dev/ttyUSB0` should be a link to `/dev/host-dev/ttyUSB0`. `make flash` puts the FreeRTOS image back. Attaching the USB device to a different WSL distro than the one running Docker leaves it invisible here. `--device=/dev/ttyUSB0` is not used, because Docker then refuses to start when the board is unplugged.

## Editor

`make`, `make blink`, and `make compile-commands` rewrite `compile_commands.json` with the flags for the selected board. `.vscode/c_cpp_properties.json` and `.vscode/settings.json` point the Microsoft C/C++ extension at that database. The dev container installs that extension and Makefile Tools. It does not install clangd.

Ctrl+Click and F12 follow a call once a language server has loaded the database. In this workspace that required the clangd extension as well; the image does not provide it, so a new container needs it installed again. If Makefile Tools offers to provide IntelliSense, decline it, or it replaces this database. **C/C++: Reset IntelliSense Database**, then the **ATmega2560** configuration, reloads the Microsoft engine.

## Another AVR

```sh
make BOARD=atmega1284p
make BOARD=atmega1284p F_CPU=20000000UL
```

Copy `boards/atmega1284p.mk` for the next part. Set `F_CPU` to the crystal you actually fit, or baud rates and timer ticks are wrong. The 1284P file leaves the LED off, leaves USB programming unset, and does not define fuses. `make flash-isp` is the programming path. Fill in the fuse bytes from `make fuses-read` before any fuse target will run.

## AVR Dragon, ISP

The Dragon ISP 6-pin plug matches the Mega ICSP header. Pin 1 is MISO on both.

```sh
make fuses-read
```

reads the three fuse bytes over ISP and writes nothing.

```sh
make flash-isp ALLOW_BOOTLOADER_ERASE=1
```

chip-erases the part, which deletes the USB bootloader. The application is linked at address 0 either way. On a stock Mega the high fuse still has BOOTRST programmed, so reset jumps into the now-empty boot section and both USB upload and the application stay silent until one of these:

```sh
make fuses-noboot ALLOW_FUSE_WRITE=1          # high fuse 0xD9, reset enters the application
make fuses-stock ALLOW_FUSE_WRITE=1           # back to the Arduino Mega fuse bytes
```

`fuses-stock` does not restore bootloader code. The Arduino AVR boards package ships that image as `stk500boot_v2_mega2560.hex`. Program it with avrdude after the stock fuses are back, then `make flash` works again.

`fuses-stock` is the only target that writes the low fuse. A wrong low fuse selects the wrong clock, and ISP then needs an external clock or the Dragon's high-voltage parallel mode. This baseline does not automate high-voltage programming.

## AVR Dragon, JTAG

A debug session uses two Dragon headers, in this order. Stock Mega high fuse `0xD8` has JTAG and on-chip debug off, so ISP writes that fuse first. The debug server then talks JTAG. The Mega has no 10-pin JTAG socket; those signals are wires to analog A4–A7, RESET, 5V, and GND. Power the Mega from its own USB port. The Dragon does not power the target.

### Enable JTAG over ISP

Plug the Dragon ISP 6-pin cable onto the ICSP header next to the ATmega2560. Pin 1 is MISO on both, and it is marked on the Dragon and on the Mega. The 6-pin header beside the USB connector programs the 16U2, not the 2560.

Attach the Dragon (USB id `03eb:2107`) with the same `usbipd` commands as the serial board, to the distro that runs Docker. `tools/99-avr-dragon.rules` is the udev rule for a native Linux host. On WSL the usbip node is often root-owned; the container runs as root, so the rule is not required there. avrdude and AVaRICE open the Dragon through `/dev/bus/usb`, which this container has only after **Dev Containers: Rebuild Container**.

```sh
make fuses-read
make fuses-jtag ALLOW_FUSE_WRITE=1
```

`fuses-read` prints the three fuse bytes and writes nothing. `fuses-jtag` writes high fuse `0x18`. Fuse bits are active-low: a programmed bit is 0. That enables OCD and JTAG, leaves SPI programming enabled, and leaves the bootloader in place, so `make flash` still works. Analog A4–A7 are then the JTAG port and are no longer analog inputs.

### JTAG cable

Pin 1 of the Dragon 10-pin JTAG header is marked on the silkscreen. Count from that pin. Pins 7 and 8 stay open.

| Dragon pin | Signal | Mega |
| --- | --- | --- |
| 1 | TCK | PF4, analog A4 |
| 2 | GND | GND |
| 3 | TDO | PF6, analog A6 |
| 4 | VTref | 5V |
| 5 | TMS | PF5, analog A5 |
| 6 | nSRST | RESET |
| 7 | leave open | |
| 8 | leave open | |
| 9 | TDI | PF7, analog A7 |
| 10 | GND | GND |

VTref lets the Dragon read the target voltage and set its level shifters. It draws under 1 mA and does not power the Mega. Pin 7 is unconnected on the Dragon and must stay open. Pin 8 (nTRST) is unused on this AVR. Connect both GND pins. nSRST lets the Dragon reset the chip, which matters if firmware later sets the JTD bit and turns JTAG off. Both cables can stay plugged in. Fuse commands use the ISP header; the debug server uses the JTAG header. Do not run avrdude and AVaRICE at the same time.

### Session

Program the image first. The debug server does not write flash; it debugs whatever is already there. `make DEBUG=1` rebuilds with `-Og` and keeps `-g`.

```sh
make DEBUG=1
make flash
```

In one terminal:

```sh
make debug-server
```

starts AVaRICE (`avarice -g -j usb --part atmega2560 -B 250 :4242`). It listens on port 4242 at 250 kHz and does not erase or program. Override the rate with `JTAG_BITRATE=` (Dragon range 22–6400) and the port with `GDB_PORT=`.

In another terminal:

```sh
make gdb
```

`make gdb` and the launch configuration "AVR Dragon JTAG" both use `build/stepper-interface.elf`, not the blink image. `tools/gdbinit` connects to `:4242`, allows 4 hardware breakpoints and 2 watchpoints, and does not issue `load`. With BOOTRST still set, the bootloader runs after reset. Stop in the application with:

```
break main
continue
```

The launch configuration sets that breakpoint itself and expects `make debug-server` to be running already.

When ISP is the only programming path and the bootloader should stay out of reset:

```sh
make fuses-jtag-noboot ALLOW_FUSE_WRITE=1     # high fuse 0x19
```

On the 1284P the JTAG pins are PC2 (TCK), PC3 (TMS), PC4 (TDO), and PC5 (TDI). `make debug-server` and `make gdb` use that board file too. It will not write fuses until you put measured values in it.

## FreeRTOS

`third_party/freertos.tag` pins FreeRTOS-Kernel V11.3.2. `tools/fetch-deps.sh` clones it if `tasks.c` is missing and applies `tools/freertos-timer0.patch`. The patch is the only change to the kernel: `configAVR_USE_TIMER0_TICK` can select Timer0. Leaving the macro unset keeps the upstream watchdog choice. The blink image does not link the kernel.
